# 监控页报告打印预览

## 目的

甲方反馈修复第2项。原监控页“报告打印预览”仅有说明和跳转按钮，并未绘制报告；现在接入与报告中心共用的报告读取、排版和打印预览服务。

## 流程

- 进入报告页签时读取当前实验并显示真实分页内容，默认显示全部页面缩略预览。
- 使用页码选择框查看单页，点击“全部页面”恢复总览；“刷新预览”重新读取当前数据。
- 保留“在报告中心打开”，打印、签署和导出继续在报告中心执行。
- 只在报告页签激活时排版；离开取消待执行刷新。实验状态或结果变化时合并刷新，不按视频帧或倒计时重绘报告。
- 切换实验、界面语言、会话或退出页面时先隐藏旧报告；进入时重新授权并读取，避免展示旧账号缓存。
- 未签署报告跟随客户端语言，已签署报告仍按现有服务使用签署时语言。本轮不改变签署及语言规则。
- 加载、数据库及绘制异常被转换为提示，可点击刷新重试；完整错误、实验标识及错误类别写入后台日志。
- Qt字体及排版在界面线程执行，避免跨线程使用Qt排版对象。

## 权限

复用现有 `report_view` 服务层授权，预览不会授予签署或导出权限。未登录及失效会话不能重新加载报告。

## 数据

无数据库修改、无开发数据清理、无新报告落盘。复用 `ReportService.preview` 和 `ReportService.paint`，与报告中心使用同一内容及排版逻辑。

## 测试

`tests/ui/test_monitor_report.py` 覆盖18管及96管真实内容和多页、逐页与总览、报告中心内容摘要一致、切换实验及语言、会话失效、绘制异常及恢复、页签延迟加载和关闭清理，以及简繁英×1024/1280两种宽度。

检查实际纸面白底和文字笔画，并生成截图，不只检查页数。相关回归覆盖现有报告渲染、签署、打印、验签、导出及架构约束。

## 用户验证步骤

1. 从历史记录打开一份已完成实验，切换到“报告打印预览”。
2. 确认真正显示该实验编号、样品、结果及报告页脚，不再只有说明按钮。
3. 多页报告选择最后一页，再点击“全部页面”，检查页数和内容。
4. 切换另一实验，确认不残留上一实验；切换语言或点击刷新，确认可重新显示。
5. 点击“在报告中心打开”，确认进入同一实验，仍可按原权限操作。

Windows及用户实际使用环境的验证仍需单独完成。
