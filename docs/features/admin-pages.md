# 数据管理页：历史记录、审计追踪、用户与权限、仪器设置、Excel 导出

对应阶段：P12。代码：`ui/pages/{history_page,audit_page,users_page,users_dialogs,settings_page}.py`，服务 `services/{audit_service,user_service,settings_service,user_settings,export_service,excel_export}.py`。数据层的补充见 [data-management.md](data-management.md)。

## 目的

给管理员和分析员日常管理系统用的四个页面，加上把数据带出软件的 Excel 导出。四个页面替换了原来的占位页；至此软件里没有“建设中”的页面了（`PlaceholderPage` 已删除）。

- **历史记录**：按试验类型、时间段、批号、状态、操作人筛选，分页，打开回看，选中导出 Excel。
- **审计追踪**：按时间段、操作者、关键字查询（序号、操作者、时间、权限、操作记录），校验哈希链，导出 Excel。
- **用户与权限**：账号列表、新建、停用和启用、重置密码、改角色，只读的角色-权限矩阵。
- **仪器设置**：仪器编号、孵育和读数参数、温度范围和告警持续时间、算法后端信息、视频输入、数据保留、版权方名称、敏感导出加密（P13）。
- **Excel 导出**：试验结果、历史列表、审计记录；报告中心设计稿里的“导出 Excel 数据”也接上了。
- **MVD 和内毒素限值**：新试验向导可选录入，固化到试验记录，显示在 PDF 报告里。

## 流程

### 历史记录

进入页面时读取第一页（每页 20 条，创建时间倒序）。筛选条件之间为“且”：批号同时匹配试剂批号和样品批号（精确）；日期按本地时区，结束日期含当天。“重置”清除全部条件。没有结果时显示空状态，并区分“还没有历史试验”和“没有符合条件的试验”。双击一行或点“打开所选试验”进入试验监控页的只读回看。点选多行（再点一次取消）后“导出所选结果…”；“导出当前列表…”导出**符合当前条件的全部试验**，不只当前页。导出在后台线程，界面不冻结，完成后提示。

### 审计追踪

查询、校验、导出都在后台线程（`BackgroundRunner`），查询卡着时界面照常响应；新的请求让没返回的旧请求作废。每页 50 条，最新在前。

- **校验完整性**：调用审计仓储的 `verify_chain`（`verify_audit_chain` 包装的同一个函数），进度条显示“已校验到 / 总数”；通过时绿色横幅“校验通过：哈希链完好，共校验 N 条”，不通过时红色横幅指出**第一处异常的序号**和原因（内容被改、与上一条衔接不上、序号不连续、链头不符），列表里那一行标红。
- **查看审计本身写审计**：新开一次查询（第一页）在查询之后写一条 `audit_viewed`，记条件；往后翻页不再写。翻页时用第一页看到的最大序号固定范围（`AuditQuery.max_seq`），期间新写入的记录不会把后面的页顶歪。校验写 `audit_verified`，导出写 `data_exported`。
- “权限”列是该事件发生时操作者的角色（参考软件的叫法）。操作记录是库里存的原文（简体中文），英文界面下也是原文，不翻译。

### 用户与权限

新建用户时登录名必填，显示名称留空则用登录名，初始密码可留空（自动生成 12 位临时密码）。**临时密码只在对话框里显示一次**，不写日志也不写审计；新账号和重置后的账号“首次登录必须改密”。停用后该账号已登录的会话立即失效；改角色后该账号已登录的会话立即采用新角色（服务层每次都重新读用户，界面这边由 `AuthService.refresh_sessions` 同步会话）。管理员改自己的角色时，主窗口立即刷新入口，当前页没有权限就回工作台。

规则（服务层，检查和写入在同一个事务里）：

- 不能停用自己；不能在这里重置自己的密码（用用户菜单里的“修改密码”）。
- 不能停用或降级**最后一个启用的管理员**。
- 每个操作同一事务写 `user_changed` 审计，审计写不进去就不生效。

### 仪器设置

所有角色可以查看；只有管理员可以修改，其他角色看到置灰的输入框和“只读”标记（服务层也拒绝）。

保存流程：整体校验（所有不合法的项一次报出，每项一句明确原因，一项都不写）→ 运行时生效（引擎配置、视频管线、仪器编号、版权方）→ 写用户配置文件 → 写审计（逐项记录**旧值和新值**）。任何一步失败，前面的步骤都撤销。改动对**之后启动的试验**生效。

| 设置项 | 允许范围 | 试验进行中 |
|---|---|---|
| 孵育时间（分钟） | 0.1–1440 | 不能改 |
| 翻转前后各取帧数 | 3–20（整数） | 不能改 |
| 翻转后稳定时间（秒） | 0–10 | 不能改 |
| 目标温度（℃）、允许偏差 ±（℃） | 20–45、0.1–5（有效范围 = 目标 ± 偏差） | 不能改 |
| 越限告警持续时间（秒） | 0–3600 | 不能改 |
| 视频输入类型与路径 | 沿用配置文件 / 视频文件 / 图片文件夹 | 不能改 |
| 仪器编号 | 1–64 个字符 | 可以改 |
| 数据保留天数 | 留空（默认，不自动删除）或 1–36500 | 可以改 |
| 版权方名称 | 1–120 个字符 | 可以改 |
| 敏感导出加密（P13） | 开 / 关（默认关） | 可以改 |

- **算法后端信息**只读：后端类路径、配置文件，以及**最近一次分析所用的模型版本和配置版本**（取自试验结果的记录；还没跑过试验时显示“第一次试验后显示”）。
- **视频输入**：没有实时摄像头这个选项（尚未实现）；工业相机只在界面上说明“型号确定后接入”。选了视频文件或图片文件夹后可以“浏览…”选路径、“预览”读第一帧并显示分辨率、帧率和帧数；预览在后台线程，不影响设置和运行中的试验。保存后下一个试验用的就是新的源（视频文件和图片文件夹都设为循环回放，试验比一段素材长得多时不会断流）。
- **敏感导出加密**（P13）：打开后 Excel 导出和批量导出报告都打成 AES-256 加密的 ZIP，每次导出前设置密码，见 [security.md](security.md#敏感导出加密)。
- **数据保留**目前只保存设置：到期自动清理的任务**尚未实现**，页面上写明了这一点，不会删除任何文件。
- 没有改动的项只检查格式，不再要求在允许范围内（默认配置里写的值可以超出界面的范围，不能因此让管理员改别的项保存不了）；没有改动的视频路径也不再检查是否存在。

### Excel 导出

用 openpyxl 只写模式，一万管约 1 秒。三种导出：

- **试验结果**（历史页选中、报告中心当前试验）：“试验”汇总（编号、类型、状态、仪器、人员、时间、三种批号、λ、MVD、限值、实测 λc、**结论**、结论数值、规则版本、管数、待复核管数）、“单管结果”（每管的样品、用途、算法状态与三态、自动判读、复核状态与最终判读、**复核人、时间、备注**、评分、置信度、**ΔA、Δs、σ_A、σ_s、面积**、模型与配置版本、耗时）、“结论依据”（计算过程和未满足的前提）。
- **历史列表**：符合筛选条件的全部试验。
- **审计**：符合查询条件的全部记录（含哈希）。

安全与格式：

- **公式注入防护**：以 `=`、`+`、`-`、`@`、制表符、回车开头的文本，前面补半角单引号，Excel 把它当普通文字显示（样品名称、复核备注、审计的操作记录都是用户输入）。测试逐个读回单元格，确认没有任何单元格是公式。
- **文件名安全**：`safe_filename` 去掉路径分隔符、控制字符、Windows 保留名，限长；保存对话框里的建议名经过它。缺 `.xlsx` 扩展名时补上；工作表名也规整（`[]:*?/\`，31 字符）。
- **中英文**：列标题和枚举值按界面语言翻译（`ui/export_labels.py` 登记全部源文本，测试保证与服务层 `EXPORT_TEXTS` 一致）；写进审计库的原文固定为简体中文。
- 先写同目录的临时文件再改名，写到一半失败不会留下损坏的文件。

### MVD 和内毒素限值

向导第 3 步（样品和管位）下方有两个可选输入框；留空则报告里不填。非法值（不是大于 0 的数）在界面上提示并挡住“下一步”，服务层也重新校验，界面被绕过也不会写入。录入的值写入试验记录（`experiments.mvd`、`experiments.endotoxin_limit`）和创建试验的审计，并显示在第 4 步和 PDF 报告里。`ExperimentService.update_limits` 允许在签署前修改（写 `limits_changed`，记旧值和新值），**已签署的试验不能改**。

## 数据

| 内容 | 位置 |
|---|---|
| 用户、角色、启用、密码哈希和“须改密”标记 | `users` 表 |
| 审计 | `audit_events` 表（哈希链），新事件类型 `audit_viewed`、`audit_verified`、`limits_changed` |
| MVD、内毒素限值 | `experiments.mvd`、`experiments.endotoxin_limit`（已有的列，无新迁移） |
| 仪器设置 | 数据目录下的 `user_settings.json`：`{"version": 1, "settings": {…只含与默认配置不同的项}}` |

用户配置文件的规则：不改仓库里的默认配置；默认配置以后更新了，没改过的项自动跟着更新；一项改回默认值就从文件里消失；文件由临时文件原子替换写入。**文件有错**（手改坏了、未知的设置项、超范围、版本不认识）时启动失败并说明怎么办（修正或删除这个文件），不会悄悄忽略后用另一套参数跑试验；此时还没有创建任何文件。

时间说明：报告上的“检测日期”取自试验开始（`ready → incubating`）事件的时间，由引擎用真实系统时钟写入；创建、签署用服务时钟。**不注入时钟时两者是同一个时间轴**（`tests/services/test_real_clock_flow.py` 检查创建 ≤ 开始 ≤ 完成 ≤ 签署，且报告显示的就是这些值）。给 `build_app_context` 注入固定时钟只作用于服务，引擎仍用真实时钟，所以 P11 自检脚本里报告的检测日期（真实）会晚于签署日期（注入的固定值）：这是注入造成的，不是真实路径的问题。
