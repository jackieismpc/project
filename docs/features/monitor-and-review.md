# 监控与结果（monitor-and-review）

对应阶段：P9。代码：`ui/pages/monitor_page.py`、`monitor_images.py`、`monitor_format.py`、`tube_detail_page.py`、`replay_dialog.py`、`history_page.py`、`dashboard.py`；`ui/bridge.py`、`ui/background.py`；`services/monitor_service.py`、`media_service.py`、`review_service.py`、`dashboard_service.py`、`mask_archive.py`、`replay.py`。视觉对照 `docs/design/Monitor.dc.html`、`TubeDetail.dc.html`、`Main.dc.html`。

## 目的

让用户跑 `uv run gelinspect` 就能看到完整流程：向导启动后进入试验监控页，实时看到孔板、倒计时、视频和结果表；点孔进单管详情，看翻转前后图和算法掩码，分析员人工复核；复核完试验转为可签署。已结束的试验可以从历史记录或工作台打开回看。

不在本阶段：报告预览和打印（P11，两个标签是占位）、历史的完整查询和导出（P12）。判定规则和结论见 [conclusions.md](conclusions.md)。

## 流程

### 数据怎么到界面

```text
引擎线程 ─EngineEvent→ engine-events 线程 ─┐
视频预览线程 ─PreviewFrame→ MonitorService ─┼→ EngineBridge（Qt 信号，排队到主线程）→ 页面
视频事件线程 ─VideoEvent──→ MonitorService ─┘
页面打开时：MonitorService.view()（数据库 + 引擎快照）取一次完整视图
```

- **预览帧**：桥在预览线程里把 BGR 数组拷成 `QImage`，只保留最新一帧；主线程还没取走时新帧覆盖旧帧。界面慢时丢帧，不堆积，也不会拖慢预览线程、采集和引擎。预览本身由管线缩放（长边 ≤960）并限制在 15 fps。
- **合并刷新**：孔更新、倒计时事件只改页面内存里的状态并请求一次刷新，单次定时器把孔板和结果表的重绘合并到每 100 ms 最多一次（≤10 Hz）；状态变化时重读一次视图。工作台的进行中卡片同理（250 ms）。
- **后台读盘**：解码 12 MP 的 PNG 要几百毫秒，单管详情的图像和“图像显示”的缩略图由 `BackgroundRunner`（Qt 线程池）读取，结果经排队信号回主线程；切换试验时过期结果丢弃。回放的 MP4 已缩到长边 1920，逐帧解码在主线程由定时器完成。
- 界面不创建线程、不碰数据库和引擎线程（`tests/test_architecture.py` 强制）；读数据走服务，服务先校验权限。

### 试验监控页

按设计稿从上到下：

1. **告警横幅**（`AlertStack`）：引擎告警（温度越限、视频断流、数据库忙 `storage_busy`、算法失败和超时、设备故障、舱门……）和视频事件（黑屏、卡帧、断流、重连失败……）。按“来源:事件码”去重，同一条只保留最新；`temperature_recovered`、`video_reconnected`、视频事件 `active=False` 自动撤销对应横幅；可手动关闭；最多同时显示 4 条，其余合并为“另有 N 条告警”。低帧率和驱动丢帧只统计，不弹横幅。别的试验的告警不显示。
2. **标题行**：模板名（内置模板按类型翻译，自定义模板原样）、试验标识、状态徽标（“第 2 排读数中”“待复核 · 4 管”“已完成”……）、实时温度（只在运行时）、“停止试验”。
3. **信息卡**：鲎试剂、内毒素、检查用水批号，标示灵敏度 λ，实测灵敏度 λc（只有结论为合格或不合格时才有值，否则 `–`），操作人（显示名），开始时间（审计里第一次“就绪 → 孵育中”）。
4. **结论卡**：结论徽标（合格、不合格、无效、待定）、λc、依据、未满足的前提或无效原因、规则版本和来源，见 [conclusions.md](conclusions.md)。没完成的试验显示临时结论（待定），不含数值。
5. **四个标签**：试验数据记录（默认）、图像显示、报告打印预览、单批次报告（后两者占位，说明 P11）。
6. **孔板**（`PlateGrid`，显示列头和倒计时）：状态随引擎更新；每排下面是倒计时 `mm:ss`（设备时间）或“读数中”“分析中”“已读数”“读数失败”“分析失败”；点孔进单管详情。读数或分析失败的孔用 `WellState.ERROR`（危险色环）。
7. **实时视频卡**（只在运行时）：管线预览帧，下方当前排和翻转状态（翻转中、翻转后、待机）、分辨率和实测帧率、算法判读耗时（最近一排）、翻转角度（`RowCaptured` 事件；回看时取特征里的 `flip_angle_deg`）；“回放第 N 排”打开回放对话框。
8. **结果表**：试管编号、样品名称、序列号、批号、稀释倍数、外加内毒素、阴阳性。双击一行进单管详情。人工复核后以复核结论为准。
9. **图像显示标签**：每排一行，左翻转前、右翻转后的整幅原图缩略图（8 连图，每侧取最后一张原图，即代表帧），后台逐排读取。文件哈希不符、文件缺失会在该排提示。

**只读回看**（试验不在运行：已完成、待复核、已停止、重启后的异常）：没有停止按钮、温度和实时视频；右侧改为“按排回放”卡，下拉选排后在卡里直接播放；孔板、结果表、图像标签照常。判断“在运行”的依据是引擎正在运行**且**试验状态在运行状态里（引擎在状态到达终点后还要收尾，期间界面已按只读显示）。

**停止试验**：只有处于孵育、读数、分析、异常状态的试验显示按钮；点击先弹确认框（危险样式），确认后调用 `MonitorService.stop`。运行中的交给 `engine.stop`（立即返回，界面随状态事件更新），没有在运行的异常试验（启动恢复标记的）走 `stop_faulted`。没有 `EXPERIMENT_STOP` 权限时按钮显示但禁用，服务层也拒绝。

### 恢复和重试

| 情况 | 入口 | 行为 |
|---|---|---|
| 异常且引擎还在运行 | “恢复试验”，先确认 | `engine.resume`：核对设备、温度和视频；读数失败的排重新翻转（确认框写明翻动过的凝胶状态可能已变，PLAN 第 7 节第 15 项），分析失败的排用原图重试。条件不满足时告警（`resume_rejected`）显示在横幅，试验保持异常 |
| 异常且有分析失败的排 | “重试分析” | `engine.retry_analysis`：从磁盘读回原图、核对哈希，不翻转。还有其他异常原因时被拒绝并告警 |
| 运行中单排分析失败 | “重试分析”禁用 | 其他排还要按时读数，全部排读完后才能重试，页面有提示 |
| 软件重启后的异常 | 只有“重试分析”和“停止试验” | 见下 |

**重启后重试**：抓帧时间和翻转角度（`media_files.captured_at`、`flip_angle_deg`，P10 起入库）和原图都在，所以已抓帧、没有结果的排可以离线重新分析，不碰设备，也不翻转（`EngineRun` 的离线模式，`services/engine_recovery.py`）。全部排都有抓帧时，完成后试验照常进入待复核或已完成。还有排没读数时，分析后回到异常，审计写明这些排错过了读数时间，试验只能停止：调度已丢失，设备状态未知，不能续读。P10 之前的记录没有抓帧时间，不能重试，页面说明原因。

需要 `experiment_run` 权限（实验员）；没有权限时按钮禁用，服务层拒绝并写 `permission_denied`。恢复和重试都以操作者身份写状态变化审计，被拒绝时写 `engine_alert`。

### 按排回放

`MediaService.open_clip` 先核对 `media_files` 里的 SHA-256（被改动的录像不播放，提示“哈希不符”），再用 OpenCV 打开；Windows 下含中文的路径先复制或硬链接到纯 ASCII 临时目录。`ReplayPlayer` 用定时器按文件帧率逐帧取图转 `QImage`，带播放/暂停、进度条和时间；播完再点播放从头开始；隐藏时自动暂停，关闭对话框释放解码器。

### 单管详情页

- 标题：`N 号管`，副标题排号、模板、外加内毒素、试验标识；“返回孔板”回到监控页。
- **翻转前后对比**：两张裁剪图。裁剪框来自该侧试管掩码的外接框，长短边各自外扩 18%（短边至少外扩长边的 6%），控件宽度按图像比例收窄，两侧不留黑边；没有掩码（算法失败、缺管）时按孔位把整幅图切成 8 列取对应一列并提示。图像下标注翻转前 0.0°、翻转后实际角度和抓帧时间。
- **掩码叠加开关**：凝胶掩码橙色 38% 填充加阳性色描边，试管掩码主色虚线。轮廓由服务层从存档的 PNG 提取（缩小后的裁剪图上 `findContours`），界面用矢量线条绘制，缩放不失真；开关只切换显示。
- **3 帧序列**：“查看 3 帧序列”展开翻转前后各 n 帧的同位置缩略图。“回放翻转视频”打开该排录像。
- **判读**：三态、融合评分条、ΔA、Δs、σ_A、σ_s（缺失显示 `–`；Δs 的单位算法侧未定，界面不写单位）；状态不是 ok 时显示处理状态和算法给出的原因。
- **判读来源**：模型版本、阈值配置版本、判读耗时（本排 n 支）。
- **人工复核**：判为阳性 / 判为阴性（二选一），复核意见必填，提交。复核后判读区显示“算法：部分凝固 → 人工：阳性”，下方显示复核人、时间和意见；**算法原始结果不被覆盖**（`gel_state`、`auto_interpretation` 保留，`reviewed_*` 另存，最终判读以复核为准）。提交按钮的可用条件：有 `RESULT_REVIEW` 权限、试验处于“待复核”、这支试管有结果；否则在下方说明原因（“当前角色没有复核权限”“全部排读数分析完成、试验进入待复核后才能复核”）。写了一半的意见，离开页面前确认。

### 人工复核与状态机

`ReviewService.review_tube`：

1. `authorize(RESULT_REVIEW)`（实验员、管理员被拒绝并写 `permission_denied` 审计）。
2. 意见去空白后必填（≤1000 字），结论只能是阳性或阴性。
3. 调用领域的 `Experiment.review_tube`：只有“待复核”状态能复核。
4. 同一个工作单元里：带预期状态更新试验（别处改过状态时 `StateConflictError` → `REVIEW_CONFLICT`，整个事务回滚）、保存这支管的结果、写 `tube_reviewed` 审计（算法三态、算法判读、人工结论、意见）。
5. 如果已没有待复核的试管，**同一事务里**应用 `review_completed`，试验转为“已完成”（可签署），写入完成时间和试验结论，并写状态变化和 `conclusion_recorded` 审计。

所有待复核处理完试验才会进入已完成，状态机和守卫由领域层保证；签署是 P11。已完成后不能再复核（需要 `reopen_review`，本阶段不提供入口）。

### 工作台

- **检测室温度**：大号读数和曲线（37±1 ℃ 范围带、中间虚线、末端实心点）；打开时用进行中（或最近一次）试验的温度日志做初始曲线，之后实时追加。
- **进行中的试验**：孔板缩略图（`MiniPlate`）、状态徽标、模板名、试管数、已完成排数和进度条、“打开监控”。
- **最近结果**：试验、类型、试管数、结果（“全部阴性”“阳性 p · 阴性 n”“n 管待复核”，未结束为空）、状态、完成时间；双击打开回看。
- **需要处理**：待复核的试验（点击打开）、异常的试验（点击打开，可在监控页停止）、距有效期 ≤30 天的试剂（“还有 N 天过期”）和已过期的试剂。没有事项显示“没有需要处理的事项”。

### 历史记录（最小入口）

列出最近 200 个试验（试验、类型、试管、状态、操作人、创建时间、完成时间），双击或“打开所选试验”进入监控页只读模式。快捷栏的“打开文件”（`Ctrl+O`）接到这里。按条件查询、导出是 P12。

## 权限

| 操作 | 权限 | 角色 |
|---|---|---|
| 进入监控、单管详情、历史；读取试验视图、图像、录像 | `experiment_view` | 全部 |
| 停止试验 | `experiment_stop` | 实验员 |
| 恢复试验、重试分析 | `experiment_run` | 实验员 |
| 复核单管 | `result_review` | 分析员 |

界面按 `session.can(...)` 禁用入口；服务层 `MonitorService`、`MediaService`、`ReviewService`、`DashboardService` 每个入口先调用 `AuthService.authorize`，拒绝时写 `permission_denied` 审计。

## 数据

- 读：`experiments`（含 `tube_results`）、`audit_events`（开始时间）、`media_files`（录像、原图、掩码）、`temperature_log`、`reagent_checks`（试剂有效期）。
- 写：三处。**复核**：`tube_results.reviewed_*`、`experiments.state`、审计 `tube_reviewed` 和 `experiment_state_changed`；最后一管还写结论和完成时间。**停止**、**恢复和重试**：交给引擎，写 `experiment_state_changed`。
- 文件：掩码存档 `<data_dir>/images/<试验>/row_XX/mask_tNN_<gel|tube>_<before|after>.png`（P9 起由引擎写，见 [experiment-engine.md](experiment-engine.md)）；原图和录像同 [video-pipeline.md](video-pipeline.md)。读图和录像时核对入库的 SHA-256：哈希不符的图仍显示但带告警，不符的录像不播放。
- 特征快照里软件补充的 `flip_angle_deg` 用于显示翻转角度。

## 已知限制

- **已完成后不能再复核**：状态机的 `reopen_review` 没有界面入口。
- **“图像显示”逐排后台读取**：12 MP 下 12 排共 24 张图要几秒，期间显示“正在读取图像”。
- **回放在主线程解码**：录像已缩到长边 1920，单帧解码很快；更大的录像需要改成后台预取。
