# 诊断包与运行日志

管理员或获“仪器与维护”权限的用户，可在“设置 → 诊断包”选择 ZIP 保存位置并导出。服务层每次重新检查 `diagnostics_export` 权限，成功导出后写入 `data_exported` 审计记录。打包在后台执行，显示文件进度并允许取消；取消后会删除临时归档，不替换已有目标文件。

诊断包采用白名单内容：

- 试验结构化快照，包括配置参数、每管样品和管位、试剂批次、算法状态/分数/置信度/特征、模型与配置版本，以及历次人工复核。
- 关联审计事件及哈希链校验值。
- 与试验关联的温度采样和设备日志。
- 数据目录内登记的原图、掩码和录像；逐个校验登记 SHA-256。
- 当前和轮转的应用日志；密码、令牌、授权头、密钥等常见键值形式会脱敏。
- `manifest.json` 列出每个归档文件的 SHA-256 和大小，以及未找到、越界或哈希不符的媒体。

服务不会复制 SQLite 数据库、账号表、配置目录、密钥目录或报告签名私钥，不导出密码及其哈希。媒体路径必须解析到数据目录内的普通文件；符号链接、越界路径、缺失文件和哈希不匹配均排除并列入清单。归档路径使用安全文件名，不直接采用媒体路径。

日志写入 `<data_dir>/logs/gelinspect.log`，达到单文件大小阈值后按时间戳归档，默认不自动删除历史日志。设置页显示日志占用及数据盘可用空间，便于维护人员判断容量。

服务级定向验证覆盖权限拒绝、秘密脱敏、媒体哈希校验、数据目录边界、取消清理、审计记账和日志轮转保留。


## 查看与访问审计

明确执行历史实验查询时记录筛选条件、分页位置、返回数量及成功、拒绝或失败结果；工作台最近列表等自动加载查询不重复记账。用户明确打开实验数据时，调用 `MonitorService.view(..., audit_access=True)` 写入查看审计，`reload()`、状态轮询和自动刷新保持默认关闭。单管图像读取和实际打开录像分别记为 `image_accessed`、`video_accessed`；只列出录像供自动播放选择、自动刷新及逐帧播放不产生访问事件。诊断包的授权拒绝、参数或文件失败、取消和成功均写入 `data_exported` 结果事件，导出成功后事件注明文件数和缺失排除数。

查看和查询的审计在读取完成后追加，读取与审计追加不是同一个数据库事务；若审计追加自身失败，服务会记录后台错误日志，不会伪报操作失败或改变只读结果。写入类业务操作仍沿用其服务事务，把业务写入和审计原子提交。本项定向回归：Query、实验查看、录像访问和诊断包服务用例共 11 项通过；相关 5 个服务源文件 mypy 通过，目标服务及测试 Ruff 通过。
