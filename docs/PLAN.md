# 凝胶试剂机器人智能检测系统：上位机软件开发计划

> 状态：已批准（2026-11-04），执行中。本文件在执行过程中实时更新每个阶段的进度。

## 1. 背景与目标

项目（合作方：厦门鲎试剂生物科技股份有限公司）要用「试管翻转 + 工业相机 + 算法判读」替代人工凝胶法。本次**只做上位机软件**：

- 离线运行，支持 Windows 和 macOS，基于 Python + PySide6（研发计划指定）。
- 功能参考视频和截图中的 ET-96AT，但界面用现代卡片式设计重做。**只参考功能，不使用其名称、Logo 或界面素材。**
- **不管硬件设计，但软件最终部署在设备上运行**：视频获取、处理、录制和抓帧都由软件实现。设备通信协议和工业相机型号定下来之前，这两处的真实驱动先用适配层隔开。
- **算法后续接入**：本次定好输入输出接口，用模拟数据跑通全流程。算法交付后只改配置和适配层，界面与业务层不改。

## 3. 架构

```text
ui/（页面、组件、主题）        只依赖 services，通过 Signal 接收更新
services/（试验引擎、报告、溯源、权限、审计）
domain/（实体、状态机、模板、判定规则）   纯 Python，不依赖 Qt 或数据库
interfaces/                  infrastructure/
  analysis.py (算法接口) ←──   analysis/adapter_template.py（供算法同事接入）
  video.py (视频源)     ←──    video/（OpenCV 相机、文件回放、工业相机模板）
  device.py (设备控制)  ←──    device/adapter_template.py（协议定后实现）
  traceability.py       ←──    db/、security/、reporting/、traceability/

simulation/（独立文件夹）     所有模拟数据和模拟实现，实现上述接口
```

源码放在 `src/gelinspect/`，配置放在 YAML，用 `analysis.backend`、`video.source`、`device.backend` 切换后端。

### 算法输入输出（整理自算法方案第 3–6 节）

```text
翻转前 n 帧 + 翻转后 n 帧（n≥3，≥1920×1080，JPG/PNG）
  → 分割（YOLOv8-seg，类别 0=gel，1=tube，imgsz=1024）→ gel_mask、tube_mask（翻转前后各一组）
  → 特征（最大连通域；面积 <50 像素记为凝胶缺失；tube_mask 建立试管坐标系）
       → 面积变化率 ΔA、轴向质心偏移 Δs、时序稳定性 σ_A、σ_s
  → 判定（Score = ω1·f(ΔA)+ω2·f(Δs)+ω3·f(σ_A)+ω4·f(σ_s)，ω 初值 0.5/0.3/0.1/0.1）
       → 完全凝固 / 部分凝固 / 未凝固
```

### 算法接口设计

算法方案的交付物是 Python 模块，所以软件只依赖**一个入口**。内部如何分割、提特征、用 ONNX 还是 TensorRT，都由算法侧决定；阈值和权重 YAML 也归算法侧，软件只记录其版本。

```python
class GelAnalyzer(Protocol):
    def load(self, config_path: Path | None) -> AnalyzerInfo: ...  # 启动时加载模型并预热
    def analyze_row(
        self, request: RowAnalysisRequest
    ) -> RowAnalysisResult: ...  # 同步，线程安全由软件保证
    def close(self) -> None: ...
```

**输入** `RowAnalysisRequest`（一排一次，默认 8 支）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `experiment_id`、`row_index` | str、int | 追溯用，算法无需理解 |
| `tubes` | `list[TubeSlot]` | 本排有样品的管位：管号、列位置 |
| `frames_before`、`frames_after` | `list[CapturedFrame]` | 各 n≥3 帧 |
| `flip_angle_deg` | float \| None | 编码器角度，用于校正坐标系 |
| `tube_spec`、`reagent_batch` | str \| None | 管型和批次，用于选择标定配置 |

`CapturedFrame` 为 `image`（`np.ndarray`，H×W×3，uint8，BGR）、`captured_at`（时间）、`source_path`（原图路径，可空）。

**输出** `RowAnalysisResult`：`analyzer_info`（模型版本、阈值配置版本）、`elapsed_ms`、`tubes: list[TubeAnalysis]`。每支试管一条 `TubeAnalysis`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tube_no` | int | 与输入管号对应 |
| `status` | enum | `ok`、`gel_missing`、`tube_not_found`、`low_quality`、`failed` |
| `state` | enum \| None | `fully_gelled`、`partially_gelled`、`not_gelled`；无法判定时为空 |
| `score`、`confidence` | float \| None | 融合评分和置信度（0–1） |
| `features` | `GelFeatures` | 见下表 |
| `masks` | `TubeMasks` \| None | 翻转前后的代表帧 gel/tube 掩码（uint8，0/255，与原图同尺寸），gel 可空；用于界面叠加和存档 |
| `message` | str \| None | 失败原因 |

`GelFeatures`：`area_before`、`area_after`（像素）；`delta_area_pct`（%）；`centroid_before`、`centroid_after`（图像坐标）；`axial_before`、`axial_after`、`delta_s`（试管坐标系）；`sigma_area`、`sigma_axial`；`gel_missing_before`、`gel_missing_after`。凝胶缺失时相关字段为 `None`，软件不做补算。

**软件与算法的职责划分**

- 算法负责：输出三态、Score、特征。**不输出阴阳性。**
- 软件负责：三态到阴阳性的映射（可配置）、试验结论、人工复核、存储和报告。
- 异常约定：单支问题放在 `status`，不抛异常；只有模型未加载等整体故障才抛 `AnalyzerError`。软件把失败的试管标记为待人工复核，绝不默认判阴性。
- 软件把 `analyze_row` 放到工作线程调用，超时（默认 2 秒，验收指标）会记录告警，但不中断流程。
- 每次调用的模型版本、配置版本、耗时、特征和判定写入数据库与审计日志，保证结果可追溯。
- `docs/algorithm-interface.md` 写给算法同事，配 `adapter_template.py` 和契约测试：算法实现接入后运行 `uv run pytest tests/contract` 即可自检。
- 推理依赖（onnxruntime 等）作为可选依赖 `[inference]`。ultralytics 依赖非 headless 的 OpenCV，所以运行环境只装 ONNX 推理，不装 ultralytics。

### 视频采集与处理

```text
VideoSource ─采集线程→ 环形缓冲（带时间戳，限制内存）
                         ├→ 实时预览：缩放后送界面，约 15fps
                         ├→ 录制：按排分段写 MP4，记录文件哈希并入库
                         ├→ 抓帧：收到翻转事件后，取翻转前后各 n 帧，存原图
                         └→ 质量检查：掉帧、黑屏、过曝、断流，告警并写日志
                                  ↓
                         RowAnalysisRequest → GelAnalyzer → 结果入库和界面
```

```python
class VideoSource(Protocol):
    def open(self, config: VideoConfig) -> VideoInfo: ...
    def read(self) -> VideoFrame | None: ...  # 由采集线程调用
    def close(self) -> None: ...
```

- **本次实现的输入**（2026-11-04 用户决定，暂不实现实时摄像头）：`FileVideoSource`（读入视频文件）、`ImageSequenceSource`（把图片文件夹当帧流）、`load_row_capture`（直接读一排翻转前后的图片交给算法）。`VideoSource` 接口保留，接相机时不用改管线。
- **工业相机**：文档要求 1200 万像素全局快门相机，SDK 取决于型号，提供 `IndustrialCameraSource` 模板，选型后实现。
- **大分辨率性能**：按 4000×3000 做压力测试。预览先缩放，录制和抓帧不阻塞界面线程，超出内存上限时丢预览帧，不丢抓拍帧。
- **存储**：`data/videos/<试验>/row_XX.mp4`，`data/images/<试验>/row_XX/`；保留时长可配置，列入完整性校验。
- **界面**：试验监控页增加实时视频和按排回放，「图像显示」展示 8 连图；设置页可选相机、分辨率、帧率并预览。

### 设备控制边界

不设计硬件，但流程需要与设备交互。软件定义指令和事件接口，协议（串口、Modbus 等）确定后写适配层：

```python
class DeviceController(Protocol):
    def move_tray(self, position: TrayPosition) -> None: ...  # 滑台进出
    def flip_row(self, row_index: int) -> FlipResult: ...  # 翻转一排，返回实际角度
    def read_status(self) -> DeviceStatus: ...  # 温度、门、连接、故障
```

### 模拟数据

- **所有模拟内容放在独立的 `simulation/` 文件夹**：合成试管图和视频、`MockAnalyzer`、模拟设备、试剂白名单、示例试验数据。主代码不引用其内容，只通过接口和配置使用；接入真实算法和设备后可直接移除。
- **不加专门的模拟标记**：界面和报告不显示模拟提示或水印，数据库也不设标记字段。
- 用 numpy 和 OpenCV 合成翻转前后的图像、掩码和视频，按配置比例产生三种状态，结果可用随机种子复现。
- 时间可加速（默认 60 倍：60 分钟孵育约 1 分钟跑完）。
- 可注入故障：温度越限、视频断流、低置信度、算法失败、过期试剂。

## 4. 界面设计

- **设计流程**：P2 先用 `artifact-design` skill 和 Design 画布出高保真设计稿（工作台、试验监控、新试验向导、单管详情、报告中心），放到可预览的私有页面给你评审。**确认后再转成 Qt 实现，实现结果逐页对照设计稿。**

- **组件**：Card、StatCard、Button（主要/次要/危险）、StatusBadge、DataTable、Toast、Dialog、向导步骤条、**PlateGrid（8×10 孔板，颜色表示状态）**。图标用内置 Lucide SVG（ISC 许可）。

  1. 登录
  2. 工作台（仪器状态、温度曲线、进行中试验、最近结果）

  4. 试验监控（实时视频、孔板、Row 倒计时、温度；四个标签与参考软件对应）

  6. 历史记录
  7. 模板管理

## 8. 风险与合规

- **Ultralytics 是 AGPL-3.0**：软件只加载 ONNX，不打包 ultralytics，但导出的权重仍可能受约束。正式交付前需甲方或法务确认合规路径，例如购买企业许可。算法方案也提到了这一点。
- **Nuitka 在 PyPI 上标为 AGPL-3.0**：P13 开始前核实其许可对编译产物的影响。若不合适，退回 PyInstaller 并加强其他防护措施。
- **PySide6 是 LGPL**：使用目录模式，保留 Qt 动态库可替换，交付时附许可声明。
- **「防破解」只能做到基础级别**：符合文档要求的「基础防反编译、防拷贝」，无法保证绝对安全。
- **数字签名**：本次使用本地自签证书，可防篡改并验真，但没有 CA 的第三方法律效力。如有合规要求，后续可换成 CA 证书。
- **验证能力有限**：
  - 我只有 macOS 环境，**Windows 无法在本机运行或打包**。我会写好脚本和构建工作流，并避开平台相关代码，但需要你在 Windows 上实测后才能算通过。
  - macOS 包未做 Apple 签名，首次打开需手动放行。
  - 没有工业相机和设备时，真实取图和控制链路测不了：实时摄像头本次不做，工业相机和设备通信要等样机联调。
  - 准确率、翻转时间等指标依赖算法和样机，模拟环境测不了。
- **模拟结果未做标记**：按你的要求不加水印。对外演示或导出报告时，内容看起来和真实结果一样，需要注意不要被当成真实检测记录。

## 9. 验证方式

- **自动测试**：`uv run pytest`，覆盖领域规则、状态机、审计哈希链（篡改可检出）、权限矩阵、报告验签和篡改检测；`pytest-qt` 走完「登录 → 新试验 → 模拟完成 → 复核 → 签署 → 导出」全流程。
- **模拟运行**：用 `uv run gelinspect --simulate` 启动，跑完 8×10 整板，检查故障注入场景（过期试剂被锁定、温度越限告警、视频断流、算法失败转人工复核）。
- **视频管线**：用文件视频源测采集、录制和抓帧；核对抓到的帧确实在翻转事件前后、录制文件可播放且哈希一致；按 4000×3000 压测长时间运行，内存不增长、界面不卡顿。
- **性能指标**：造 10 万条审计记录和 1 万管结果，测界面响应 <1s、查询 <1s、批量导出 <10s。
- **视觉检查**：每个页面离屏截图，由我对照设计稿审查；关键页面按简体、繁体、英文各查一次，确认没有文字溢出。
- **离线检查**：测试中禁止网络访问，确认运行时不发起任何外部连接。
- **打包检查**：在 macOS 上构建并启动 `.app`；Windows 由你运行构建产物，按 `docs/deployment.md` 的清单验证。
- **接口检查**：契约测试同时跑 `MockAnalyzer` 和一个按 `adapter_template.py` 写的假后端，确认仅改配置就能切换，界面和业务层无需改动；临时移走 `simulation/` 后，主代码仍能导入。
