## 硬件（下位机、相机）

软件已定义设备接口 `DeviceController` 和视频源接口 `VideoSource`（见 [architecture.md](architecture.md)、[video-pipeline.md](features/video-pipeline.md)），目前用模拟实现联调。真实设备接入需要以下信息。

| 序号 | 事项 | 软件需要什么 | 软件当前做法 |
|---|---|---|---|
| H1 | 上下位机通信协议 | USB 通信方式（虚拟串口、Modbus 或自定义）、指令集、应答和超时、状态与故障码、心跳 | 设备适配模板 `infrastructure/device/adapter_template.py` |
| H2 | 下位机上报的数据 | 翻转实际角度（编码器读数，算法用来校正坐标系）、加热平台温度、防护罩开合、急停、故障码 | 接口已含角度、温度、门状态和故障 |
| H3 | 设备运行日志 | 下位机日志是否上传、格式 | 上位机记录全部指令、状态和告警 |
| H4 | 相机型号和 SDK | 型号、接口（USB3.0 或 GigE）、SDK 能否随软件分发、支持的操作系统 | 支持视频文件和图片输入；工业相机模板 `infrastructure/video/industrial_template.py` |
| H5 | 相机安装和触发 | 固定还是随夹具移动；视野是否覆盖整排 8 支；软件触发还是下位机硬件触发 | 一台相机拍一排，软件在翻转前后取帧 |
| H6 | 图像方向 | 图像中 1 号管在左还是右；翻转后图像是否倒置 | 1 号管在左，翻转后图像不旋转 |
| H7 | 拍摄时机 | 翻转完成后多久开始拍、帧间隔、帧率（算法要求连续 ≥3 帧） | 翻转后稳定 1 秒，前后各取 3 帧 |
| H8 | 光源和曝光 | 背光由谁控制；曝光、增益是否需要在软件中调整 | 写在配置文件中 |
| H9 | 管号与物理位置 | 第 1 排对应的机械坐标（编号规则已定：第 1 排为 1～8 号） | 软件已按 96 管、12 排编号 |
| H10 | 各排读数时差 | 12 排同时到时、按排依次翻转，每排约 10 秒，最后一排比第一排晚约 2 分钟。是否能缩短（例如加快翻转），是否需要各排错开上样和计时 | 各排统一计时，每排实际保温时长记入记录和报告；晚于到时 120 秒告警 |
| H11 | 翻转或拍照失败后的处理 | 某排翻转失败时下位机的状态和复位方式；能否安全地重新翻转该排（翻动过的凝胶可能已改变），还是该排作废 | 操作人员确认后可重新翻转读数，并在记录中注明 |

## 算法

### 算法仓库现状（2026-11-07 核查）

本地 clone 的 `yolov8seg_tubegel/`（已加入 `.gitignore`）**目前还没有凝胶判读算法**：

- 内容是 Ultralytics 8.4.174 官方源码的副本，共 3 次提交（2026-10-10），作者只加了一个示例脚本 `tools/predict-segment.py`。
- 示例用 COCO 通用预训练模型 `yolov8x-seg.pt` 分割 4 张手持单支试管的照片。没有 gel/tube 类别、自训练权重、数据集或标注。
- 没有 ΔA、Δs、σ、Score、三态判定，没有整排输入、多帧时序和管号排序。
- 没有可调用的接口：脚本导入即执行，输入是写死的目录，结果写成文件，未检出时只打印。
- `LICENSE` 文件里残留 git 合并冲突标记（AGPL-3.0 与 Apache-2.0 两段并存）。

所以方案中的算法问题**一项都还没有被代码回答**。

### 需要算法同事按软件接口开发

接口说明见 [algorithm-interface.md](algorithm-interface.md)，自检命令 `uv run pytest tests/contract`。

| 序号 | 事项 | 软件的要求 |
|---|---|---|
| A1 | 交付形式 | Python 模块，实现 `GelAnalyzer`（`load`、`analyze_row`、`close`），导入时不执行推理、不联网 |
| A2 | 运行环境 | Python 3.11；推理用 ONNX Runtime；运行时不依赖 Ultralytics，不安装非 headless 的 OpenCV（会与界面库 Qt 冲突）；权重文件随软件分发 |
| A3 | 输入 | 一排 8 支，翻转前后各 ≥3 帧，整排 BGR `ndarray` 加管位信息，以及翻转角度 |
| A4 | 输出 | 每支管：三态、Score、置信度、特征（ΔA、Δs、σ_A、σ_s）、翻转前后 gel/tube 掩码；单支失败用状态码表示，不抛异常；不输出阴阳性 |
| A5 | 速度 | 一排 8 支判读 ≤2 秒（研发计划验收指标），在交付的上位机上测 |
| A6 | 判定指标 | 指标个数（方案说三类，公式有 4 个权重）、Score 方向、Δs 单位、凝胶缺失时的判定，需在算法文档中写明 |
| A7 | 置信度 | 提供判定置信度，供软件决定是否转人工复核 |
| A8 | 标定配置 | 阈值和权重随算法以配置文件更新，配置带版本号，软件会记录每次判读用的版本 |
| A9 | 许可 | 澄清 `LICENSE` 冲突；Ultralytics 为 AGPL-3.0，商用闭源需企业许可（已列入甲方确认事项） |
